# Segurança

Não publique credenciais, dados pessoais ou detalhes de uma vulnerabilidade em issues, pull requests ou comentários públicos. Se uma credencial tiver sido exposta, revogue-a ou rotacione-a imediatamente junto ao provedor: remover o texto do arquivo não a invalida e o histórico pode continuar contendo cópias.

Para relatar uma vulnerabilidade, use o recurso **Security → Report a vulnerability** do GitHub se estiver habilitado. Caso não esteja, entre em contato com os mantenedores por um canal privado já conhecido; não há endereço público de segurança configurado neste repositório. Inclua apenas os detalhes necessários, sem compartilhar segredos ativos.

Mantenedores: configurem o reporte privado de vulnerabilidades antes da abertura pública e revisem histórico Git, metadados e anexos. Uma varredura automatizada reduz riscos, mas não garante ausência de dados sensíveis.
